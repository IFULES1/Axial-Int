# Snapshot — 2026-08-12 (Auth locale — dev sans Supabase)

## Objectif
Implémenter un mode auth LOCAL (dev) pour dérouler tout le parcours sans Supabase
(bloqué par la limite 2 projets + upsell compute Pro). Supabase réservé à la prod.

## Décision
- Auth abstraite derrière le module `auth`. **AUTH_MODE=local** (dev) vs **supabase** (prod).
- Les deux émettent des **JWT HS256 signés avec SUPABASE_JWT_SECRET, claims Supabase-shaped**
  → decode_token + tout le reste identiques. Frontend passe TOUJOURS par backend /auth/* (pas supabase-js) → un seul chemin.
- Alternatives évaluées (Clerk, GoTrue seul, SuperTokens…) : choix prod différé, sans lock-in (DB = Postgres pur).

## Implémenté (terminé)
- `config.py` : `auth_mode: Literal["local","supabase"]="local"`, jwt_ttl_seconds=3600, refresh_ttl_seconds=30j.
- `auth/models.py` : `DevUser` (id UUID, email unique, password_hash, full_name, is_admin, created_at).
- `auth/local.py` : hash_password/verify_password **PBKDF2-HMAC-SHA256 (stdlib, 200k rounds, zéro dep)** ;
  `_issue_tokens()` (access+refresh JWT, claims sub/email/aud=authenticated/role/user_metadata{full_name,is_admin,onboarding_complete}/app_metadata) ;
  register/login (onboarding_complete calculé depuis memory).
- `auth/service.py` : register/login **dispatch sur auth_mode** ; politiques invitation + **freemail** appliquées AUX DEUX modes.
- `auth/router.py` : register/login prennent `db` (Depends get_db).
- `scripts/seed_users.py` : utilise SessionLocal + db.
- Migration `0006_dev_users.py` (+ index email unique). env.py importe auth.models.
- `.env` : AUTH_MODE=local, SUPABASE_JWT_SECRET=<dev hex32>, ALLOW_FREEMAIL=false.
- Tests `tests/test_local_auth.py` : hash roundtrip, register→JWT valide (decode_token OK), freemail bloqué, login OK/mauvais mdp 401, doublon email. **45 passed**.
