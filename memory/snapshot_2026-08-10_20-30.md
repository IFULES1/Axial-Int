## PII (terminé) — `app/modules/pii/`
- `redaction.py` : regex EMAIL/IBAN/PHONE_FR/NIR/CREDIT_CARD → `redact(text)`→(texte, mapping) + `restore()` (démasquage réversible). Ordre : email, iban, **phone avant credit_card** (sinon la carte avale le tel). Fix : retiré le `\b` initial du phone (empêchait `+33…`).
- `client.py` : `guard_outbound(text)` selon mode (`pii_guard_mode`): off=passthrough, shadow=log seulement (envoie l'original), enforce=redaction structurée + NER Presidio best-effort (`_presidio_entities` timeout 2s, fallback regex si sidecar down). Ne bloque JAMAIS.
- **Câblé** : `analysis.run_analysis` et `intelligence.post_message` appellent `guard_outbound(prompt)` avant l'envoi au provider.

## Worker + Watches (terminé) — `app/modules/watches/` + `worker/`
- `models.py` : `Watch` (user_id, name, query, analysis_type, cadence daily/weekly/manual, status active/paused, email_recipients JSON, last_run_at, next_run_at indexé).
- `service.py` : CRUD + set_status + delete ; `_next_run(cadence)` (daily +1j, weekly +7j, manual=None) ; **`run_watch(db, watch)`** (check crédits → run_analysis + memory context → finalize (débit+archive) → email → reschedule ; dégradé/insuffisant = skip+reschedule ; **ne lève jamais**) ; **`run_due_watches(db)`** (toutes les watches actives dont next_run_at ≤ now).
- `email.py` : `send_email()` SMTP best-effort (False+log si non configuré).
- `router.py` : POST/GET /watches, /{id}/pause, /{id}/resume, /{id}/run (trigger manuel), DELETE.
- `worker/main.py` : BlockingScheduler APScheduler, tick 60s → run_due_watches. `make worker`. Stateless (état = next_run_at en DB).
- Migration `0005_watches.py` (+ index user_id, next_run_at).
- Deps : `apscheduler>=3.10`.
