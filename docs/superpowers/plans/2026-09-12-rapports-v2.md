# Rapports v2 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Rendre la génération de rapports suivie, honnête et gérable : statut par identifiant avec vraies étapes, Stop, reprise après rechargement, aperçu des sources avant débit, débit atomique, bandeau dégradé et signalement, gestion complète des rapports (supprimer, renommer, archiver, classer, chercher, comparer, partager, exporter), livraison Drive, solde et écran crédits unifiés, et solde de la dette 10-18 du bilan.

**Architecture:** Backend FastAPI (`app/modules/analysis`, `app/modules/reports`, `app/modules/viz`, `app/modules/integrations`), une migration `0023_rapports_v2`, moteur de génération unique piloté par une ligne `reports` (statut/étape/progression) exécuté en thread avec sa propre session ; SSE et polling lisent le même état. Front Next.js monolithe (`App.jsx`, `bridge.js`, `globals.css`) + route serveur `frontend/app/p/[pseudo]/[slug]/page.tsx` pour le partage public. Tests pytest (SQLite mémoire, LLM et recherche simulés) + tests Node.

**Tech Stack:** FastAPI, SQLAlchemy, Alembic, ReportLab, Next 14 (App Router), React 18.

**Spec:** `docs/superpowers/specs/2026-09-12-rapports-v2.md` — l'autorité ; chaque tâche cite ses sections. Bilans de référence : `docs/superpowers/specs/2026-09-11-bilan-rapports*.md`.

## Global Constraints

- Registre : vouvoiement pour tout texte d'app ; aucun changement de prompt système (les prompts sont en relecture chez Miradie).
- Zéro régression : `PYTHONPATH=. .venv/bin/pytest -q`, `.venv/bin/ruff check app tests`, `npm --prefix frontend test`, `cd frontend && npm run build` verts.
- i18n : toute chaîne visible via `t()` FR + EN ou `libelle()` + `LABELS_EN`.
- Aucune nouvelle dépendance npm ; côté Python, seulement ce qui est déjà dans `requirements.txt` (vérifier `python-docx` ; sinon export DOCX en HTML `.doc`).
- Une seule migration `alembic/versions/0023_rapports_v2.py`, `down_revision = "0022_conversations_v2"`, réversible, index concurrents guardés PostgreSQL.
- Le build Next ne détecte pas les identifiants indéfinis : grep après toute suppression ; jamais `npm run build` pendant `next dev`.
- Sélecteur de profondeur : clés i18n et CSS **conservés**, rien branché.
- Jamais de push ni de déploiement depuis une tâche ; pas de sous-agents.

### Task 2 : Moteur de génération suivi — statuts, étapes, Stop, aperçu des sources, débit atomique, `/run`

**Spec :** §0 (`/run`), §1, §2, §3 (statut/raison), §5.1, §5.8.

**Files:** Modify `app/modules/analysis/service.py`, `app/modules/analysis/router.py`, `app/modules/analysis/schemas.py`, `app/modules/reports/service.py`, `app/modules/reports/router.py`, `app/shared/search/orchestrator.py` (si un compteur/score de pertinence doit remonter), `tests/test_troncature.py`. Test `tests/test_rapports_v2.py`.

**Interfaces :**
- `service.lancer_rapport(db, user_id, *, query, analysis_type, title, top_k, is_admin) -> Report` : crée la ligne `en_cours` et démarre le thread (`_executer_rapport(report_id)`).
- `_executer_rapport` : ouvre `SessionLocal()`, écrit `etape/progression/detail` à chaque étape (`recherche` → `selection` → `couverture` → `redaction` avec `detail.section = "3/8"` calculé à partir des titres `##` du texte reçu en flux → `finalisation`), vérifie `annulation_demandee` entre étapes et toutes les N chunks, termine dans **une transaction** : contenu + sources + viz + tokens + coûts + `statut='termine'` + `consume_credits` (échec → rollback, `statut='echec'`).
- Couverture (§2) : `_evaluer_couverture(question, sources) -> "oui"|"partiel"|"non"` (jugement tier `chat`, 200 tokens, stub-able) ; `non` ou < 5 sources pertinentes → `statut='sources_insuffisantes'`, `detail.sources` (liste titre/url/domaine), aucun débit ; `partiel` → génération et `detail.raison='couverture_partielle'`, bandeau.
- Routes : `POST /analysis/stream` (crée + suit : événements `{step: etape, progression, detail}` toutes les 2 s tant que `en_cours`, puis `done` avec `data` = `ReportDetail` + `balance`), `POST /analysis/run` (crée, attend, renvoie `ReportDetail`), `POST /reports/{id}/annuler`, `POST /reports/{id}/relancer {question?, elargir?: bool, forcer?: bool}` (nouveau rapport ; `elargir` = angles supplémentaires générés une fois ; `forcer` = générer malgré `non`), `GET /reports/{id}` renvoie statut/étape/progression/détail.
- Événement `done.data.balance`.

- [ ] Step 1 : moteur + statuts + transaction unique ; test « échec d'archivage → rien débité, statut echec ».
- [ ] Step 2 : étapes réelles + section en cours ; test de la séquence d'événements.
- [ ] Step 3 : annulation ; test (drapeau posé pendant la rédaction simulée → `annule`, non débité).
- [ ] Step 4 : couverture + relance élargie/forcée ; tests (`non` → pas de débit ; `forcer` → débit + raison ; `elargir` → seconde recherche une seule fois).
- [ ] Step 5 : `/run` = même moteur ; le test de survie de `test_troncature.py` couvre le moteur (adapter) ; test que `/run` et `/stream` produisent la même ligne.
- [ ] Step 6 : pytest, ruff, commit « Rapports v2 : génération suivie par identifiant, Stop, aperçu des sources, débit atomique ».
