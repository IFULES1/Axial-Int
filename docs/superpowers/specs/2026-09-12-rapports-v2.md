# Rapports v2 — spécification (12/09/2026)

Sources : `2026-09-11-bilan-rapports.md` (+ backend, frontend) et les retours
de Miradie du 12/09. Ce document est l'autorité ; le plan
`docs/superpowers/plans/2026-09-12-rapports-v2.md` en découle.

## 0. Arbitrages

- **Prompts système** : extraits dans `2026-09-12-prompts-rapports.md` pour
  relecture par Miradie ; aucune modification de contenu de prompt dans ce
  chantier (ses versions seront réinjectées ensuite, diff + OK avant déploiement).
- **Tuile « Étude personnalisée »** : conservée telle quelle (envoie
  `synthese_executive`) en attendant les nouveaux prompts ; le prix reste 40.
  Décision reportée avec les prompts.
- **Sélecteur de profondeur** : non branché ; les clés i18n et le CSS préparés
  sont **conservés** (retirés seulement du décompte de code mort).
- **Chemin bloquant `/analysis/run`** : conservé comme repli du flux (le front
  l'appelle quand le SSE n'ouvre pas), mais il devient un simple appelant du
  même moteur suivi par identifiant (§2) : il crée la ligne de rapport, lance
  la tâche et **attend** son terme. Une seule implémentation, un seul test de
  survie. Pas de seconde voie.
- **Google Drive** : le backend est prêt (OAuth `drive.file`, dépôt du PDF).
  Le front est branché (tuile Connexions, bouton « Drive » dans l'éditeur),
  affiché seulement si le backend déclare le fournisseur configuré. Les
  identifiants OAuth (`GOOGLE_CLIENT_ID` / `GOOGLE_CLIENT_SECRET`, écran de
  consentement, URI de redirection `https://app.axial-ia.fr/api/integrations/google/callback`)
  doivent être créés par Miradie dans Google Cloud ; la procédure est dans le
  récap. Sans eux, la tuile n'apparaît pas.
- **Partage public** : page `https://app.axial-ia.fr/p/<pseudo>/<slug>-<jeton>`
  rendue par Next (route serveur), lisant `GET /api/partage/{jeton}` (public,
  sans authentification, rapport en lecture seule, graphiques inclus, sans
  coût ni sources internes de documents). Le pseudo est dérivé du nom ou de
  l'email (partie avant `@`, normalisée), le slug du titre, le jeton de 22
  caractères aléatoires rend l'URL non devinable. Le partage se révoque.
- **Comparaison** : vue à deux colonnes de deux rapports choisis dans la
  liste, synchronisée au défilement, sans fusion ni LLM.
- **Export supplémentaire** : Markdown (`.md`) et DOCX (via `python-docx`,
  déjà dans `requirements.txt` ? sinon HTML `.doc` compatible Word — à
  vérifier par l'implémenteur, pas de nouvelle dépendance lourde).

## 1. Génération suivie par identifiant

- Une ligne `reports` est créée **au lancement** : `statut` ∈ `en_cours |
  termine | echec | degrade | annule | sources_insuffisantes`, `etape` (texte
  court), `progression` (0-100 réels), `detail` JSON (sources trouvées,
  section en cours, message), `question` (la question d'origine),
  `termine_at`. Le contenu est vide jusqu'au terme.
- La tâche tourne dans un thread avec sa propre session (mécanisme existant),
  écrit sa progression en base à chaque étape : `recherche` (par angle,
  compte de sources), `selection` (rerank, N retenues), `redaction`
  (sections détectées au fil du texte : « section 3/8 » à partir des titres
  `##` produits), `finalisation` (viz, PDF-ready).
- `POST /analysis/stream` émet les mêmes étapes en SSE (progression réelle,
  plus de battement fictif à +3 %) ; `POST /analysis/run` attend le terme et
  renvoie le rapport ; `GET /reports/{id}` renvoie statut + progression : le
  front reprend une génération en cours après rechargement (polling 3 s tant
  que `en_cours`).
- **Stop** : `POST /reports/{id}/annuler` → drapeau `annulation_demandee`
  lu par la tâche entre deux étapes et pendant le flux du modèle ; statut
  `annule`, non facturé, ligne conservée (relançable).
- **Modifier la question** : « Modifier et relancer » sur un rapport
  `annule`, `echec`, `sources_insuffisantes` ou `termine` : ouvre la question
  pré-remplie, crée un **nouveau** rapport (l'ancien reste).
- **Régénérer** : même question, nouveau rapport, débit normal. Pas de
  régénération par section (hors périmètre, coût/complexité).
- Débit **dans la même transaction** que l'archivage du contenu (§5).

## 2. Aperçu des sources avant débit

- Après la recherche et le rerank, avant le modèle : score de couverture =
  nombre de sources dont le score de pertinence dépasse le seuil du reranker
  + un jugement rapide du modèle en tier `chat` (« ces extraits permettent-ils
  de traiter la question ? oui / partiel / non », 200 tokens).
- Si `non` (ou moins de 5 sources pertinentes) : statut
  `sources_insuffisantes`, **aucun débit**, le front affiche les sources
  trouvées et propose : « Reformuler la question », « Recherche élargie »
  (relance avec des angles supplémentaires générés par le modèle à partir de
  la question et du profil, une seule fois), « Générer quand même » (débit
  normal, bandeau « couverture partielle » sur le rapport).
- Si `partiel` : la génération continue, le rapport porte le bandeau
  « Sources partielles » (§3).

## 3. Rapport dégradé et signalement

- `statut = degrade` et `detail.raison` (`truncated_generation`,
  `llm_unavailable`, `empty_generation`, `investors_unavailable`,
  `couverture_partielle`) sont exposés par l'API et rendus en bandeau
  explicite en tête du rapport, avec la raison en clair.
- Bouton « Signaler un problème » sur tout rapport → formulaire dans l'app
  (motif : contenu faux / hors sujet / incomplet / autre, commentaire libre)
  → table `report_feedback` (rapport, utilisateur, note 1-5 facultative,
  motif, commentaire, date). « Votre avis » devient ce formulaire (le Google
  Form disparaît). Un signalement envoie l'email technique à Miradie
  (notifier existant, action « relire le rapport »).

## 4. Gestion des rapports

| Action | Backend | Front |
|---|---|---|
| Supprimer | `DELETE /reports/{id}` (existant) | menu ⋯, confirmation |
| Renommer | `PATCH /reports/{id} {title}` | inline |
| Archiver | `PATCH {archived: bool}` (colonne `archived_at`) | section « Archivés » repliée |
| Classer | dossiers = mêmes `projects` que les conversations (`reports.project_id`, nullable) ; `PATCH {project_id}` | groupes par dossier, « Déplacer vers… » |
| Rechercher | `GET /reports/search?q=` (titre + contenu, extrait) | champ dans la liste |
| Liste | `GET /reports?limit=20&before=` avec `statut`, `analysis_type`, `credits`, `tokens`, `project_id`, `pinned_at`, tri : en cours d'abord, puis date | type, coût, date, badge statut, pagination « Charger plus » |
| Coût | `ReportDetail` expose `tokens_entree`, `tokens_sortie`, `credits` ; `cout_micro_eur` et coût de recherche **admin seulement** | pastille « 25 crédits · 41 k tokens » |
| Partage | `POST /reports/{id}/partage` → jeton ; `DELETE …/partage` ; `GET /partage/{jeton}` public | bouton « Partager », lien copiable, révoquer |
| Comparer | — | sélection de deux rapports → vue côte à côte |
| Exporter | `GET /reports/{id}/export?format=pdf|md|docx` | menu Exporter |
| Livrer | Notion (existant), Drive (`POST /integrations/google/deliver`, existant) | boutons selon fournisseurs connectés |

Ouvrir un rapport en échec passe par `decrireErreur` + carte d'erreur (plus
de `catch` vide).

## 5. Dette backend

1. **Transaction unique** : débit + création/mise à jour du rapport + viz
   dans un seul commit (le statut `en_cours` existe déjà ; à la fin :
   contenu + débit + `termine` ensemble ; échec → `echec`, rien débité).
2. `POST /reports` : réservé aux imports (`is_admin`) ou supprimé si aucun
   appelant (grep front + scripts) — l'implémenteur tranche et documente.
3. Images viz : `GET /viz/{empreinte}.svg` exige soit l'authentification,
   soit un paramètre `p=<jeton de partage>` valide ; `Cache-Control` privé
   court (1 h). Le front ajoute le jeton sur la page publique.
4. Rapport offert : contrainte unique `(user_id, action)` sur `credit_events`
   pour l'action `premier_rapport` (index partiel), gestion de l'`IntegrityError`.
5. Import hérité : colonne `legacy_verifie_at` sur `credit_balances` ou table
   `users_meta` (choisir la plus simple) ; `restore_for` ne tourne qu'une fois
   par compte ; retiré de `reset-password`.
6. Coût de recherche exposé (admin) ; tarifs fournisseurs sortis dans
   `config.py` (`TARIF_RECHERCHE_<FOURNISSEUR>_MICRO_EUR`) avec les valeurs
   actuelles comme défaut et un commentaire « à confirmer ».
7. Une seule table d'alias (`prompts._ALIASES` importée par `catalog`),
   `ANALYSIS_PROMPTS` supprimé (tests adaptés), cache investisseurs borné
   (TTL + verrou, documenté mono-worker).
8. `/analysis/run` = appelant du moteur suivi (§0), test de survie unique.
9. CSS mort de l'éditeur trois colonnes retiré ; clés i18n « donnée
   insuffisante / sources en désaccord » retirées ; clés de profondeur
   **conservées**.
10. Promesse d'onboarding : « ~30 s » → « quelques minutes, vous recevrez un
    email ».

## 6. Front — attente, solde, écrans

- Écran de génération piloté par l'état du rapport (SSE puis polling) :
  étapes réelles, compte de sources, section en cours, chrono qui ne se fige
  pas, bouton Stop, « Vous pouvez naviguer ailleurs » vrai : la liste montre
  le rapport « en cours » avec sa progression et l'ouvre au clic.
- Solde rafraîchi depuis le payload final (`balance`) et à l'ouverture de la
  liste ; **un seul** écran crédits : la `ModaleCredits` des conversations
  remplace `ReportsQuota` (composant supprimé).
- Parité PDF : une feuille `@media print` pour l'éditeur (marges, sauts
  avant les titres de niveau 2, tableaux non coupés, graphiques à 100 %),
  et le PDF ReportLab garde la même structure de sections ; un test compare
  la liste des titres H2 entre le markdown et le PDF généré.
