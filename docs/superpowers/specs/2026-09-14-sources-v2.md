## 0. Décisions produit

1. La base investisseurs répond aussi en conversation quand la question parle
   de levée, d'investisseurs ou de financement.
2. Chaque recherche porte des **contraintes** dérivées de la question et du
   type de rapport : fraîcheur (âge maximal des sources), domaines à
   privilégier ou exclure. Les sources trop peu pertinentes pour la question
   (score du reranker sous un seuil) sont écartées du contexte.
3. **Pappers** (registre des entreprises) alimente l'étude de marché et la
   cartographie concurrentielle : fiches des sociétés nommées dans la question
   ou repérées par le modèle.
4. La **base de connaissance Axial** (déjà peuplée : 79 078 vecteurs, ~250
   documents ingérés en août par `scripts/ingest_knowledge_base.py`) devient
   alimentable par un admin depuis l'app, avec tout type de corpus : fichiers
   (PDF, DOCX, XLSX, CSV, TXT, MD) et pages web ; l'existant reste et
   apparaît dans la liste.
5. Les agents de veille ne changent pas.
6. **Google Drive** devient une source : l'utilisateur choisit des fichiers de
   son Drive, Axial les importe comme documents (mêmes règles que l'import
   local).
7. La recherche web est **à niveaux** : niveau 1 (le plus performant), puis
   niveau 2, puis niveau 3, chaque niveau n'étant interrogé que si le niveau
   précédent n'a pas fourni assez de sources **pertinentes** pour la question.
   Perplexity rejoint la stack. Les trois moteurs actuels restent.
8. Les prompts de rapport ne changent pas (sujet ouvert, séparé).

Clés à fournir par Miradie dans Doppler (`prd`) : `PERPLEXITY_API_KEY`,
`PAPPERS_API_KEY`, `GOOGLE_CLIENT_ID`, `GOOGLE_CLIENT_SECRET`, et pour le

## 1. Contraintes de recherche (`app/shared/search/contraintes.py`)

```python
@dataclass(frozen=True)
class Contraintes:
    fraicheur_jours: int | None = None       # None = pas de filtre
    domaines_inclus: tuple[str, ...] = ()    # privilégier (Exa/Tavily/Linkup includeDomains)
    domaines_exclus: tuple[str, ...] = ()
    seuil_pertinence: float = 0.30           # score reranker minimal
    garde_minimale: int = 3                  # on garde au moins N sources même sous le seuil
```

`contraintes_pour(question: str, analysis_type: str | None = None) -> Contraintes`
— fonction pure, testée :
- Par type de rapport (défauts, surchargés par les mots de la question) :
  `analyse_reglementaire` → 365 j, domaines inclus officiels FR/UE
  (`legifrance.gouv.fr`, `eur-lex.europa.eu`, `economie.gouv.fr`,
  `service-public.fr`, `amf-france.org`, `cnil.fr`, `europa.eu`,
  `senat.fr`, `assemblee-nationale.fr`) ; `analyse_risques` → 365 j ;
  `veille_technologique` → 365 j ; `analyse_concurrentielle` → 730 j ;
  `etude_marche` → 730 j ; `synthese_executive` → 730 j ;
  `cartographie_investisseurs` → 730 j ; conversation (`None`) → aucun
  filtre par défaut.
- Mots de la question (FR/EN, insensibles à la casse) : « actualité, récent,
  dernier, dernière, cette semaine, ce mois, this week, latest, news » → 90 j ;
  « 2026, cette année, this year » → 365 j ; « loi, décret, règlement,
  directive, RGPD, DSA, DMA, AI Act, réglementation, regulation, compliance »
  → 365 j + domaines officiels ; « historique, depuis 20xx, évolution sur »
  → aucun filtre de fraîcheur. La règle la plus restrictive gagne.
- Domaines exclus par défaut partout : `pinterest.com`, `facebook.com`,
  `instagram.com`, `tiktok.com`, `quora.com`.

Propagation : `providers.<X>.search(query, limit, contraintes=None)` —
Exa : `startPublishedDate` (ISO), `includeDomains`, `excludeDomains` ;
Tavily : `days` (si ≤ 365) ou `time_range` (`year`), `include_domains`,
`exclude_domains` ; Linkup : `fromDate`, `includeDomains`, `excludeDomains` ;
Perplexity : `search_recency_filter` (`month` si ≤ 31 j, `year` si ≤ 365 j),
`search_domain_filter` (inclus, ou exclus préfixés `-`, 10 max). Les
domaines inclus sont **privilégiés, pas exclusifs** : si un fournisseur ne
rend rien avec les domaines inclus, l'orchestrateur relance sans eux (une
seule fois) pour ne pas produire un rapport vide.

Filtre de pertinence : `rerank.rerank(query, results, top_k, contraintes)`
écarte les résultats dont le score Cohere est < `seuil_pertinence`, en gardant
au moins `garde_minimale` résultats (les meilleurs). Sans Cohere : pas de
filtre (ordre heuristique inchangé). Le nombre écarté est journalisé et
remonté dans `compteur["ecartes"]`.

## 2. Recherche à niveaux (`orchestrator.py`)

Config `search_tiers: str = "perplexity,exa|tavily,linkup"` (niveaux séparés
par `|`, fournisseurs par `,`) ; `search_providers` reste lu comme repli si
`search_tiers` est vide. Un fournisseur sans clé est ignoré ; un niveau vide
est sauté.

`search(query, top_k, contraintes, compteur)` et `search_multi(...)` :
1. Interroger tous les fournisseurs du niveau 1 (en parallèle, comme
   aujourd'hui), dédupliquer, reranker contre la question, appliquer le seuil.
2. Si le nombre de sources pertinentes (score ≥ seuil) < `top_k`, interroger
   le niveau 2 et fusionner le pool (rerank sur le pool complet), puis le
   niveau 3 si besoin.
3. Arrêt dès que `top_k` sources pertinentes sont réunies. `compteur` compte
   les appels par fournisseur et `compteur["niveaux"]` le nombre de niveaux
   utilisés.
Le journal indique par niveau : bruts, dédupliqués, pertinents.

Perplexity (`providers.PerplexityProvider`, nom `perplexity`) : POST
`https://api.perplexity.ai/chat/completions`, modèle `sonar` (config
`perplexity_model_chat`), `return_related_questions=false`,
`search_recency_filter` / `search_domain_filter` selon contraintes, prompt
système « Réponds en listant les faits sourcés » ; les `search_results` (ou
`citations`) de la réponse deviennent des `SearchResult` (titre, url, extrait
= `snippet` fourni ou passage de la réponse qui cite `[n]`, `published_at` si
`date` fourni). Tarif `tarif_recherche_perplexity_micro_eur = 5_000` (sonar,
≈ 5 $ / 1 000 requêtes, « à confirmer »).

## 3. Pappers (`app/shared/enrich/pappers.py`)

- `disponible()` : `pappers_api_key` non vide.
- `rechercher(nom: str) -> dict | None` : GET `https://api.pappers.fr/v2/recherche`
  (`q`, `api_token`, `par_page=3`) → première entreprise avec `siren`.
- `fiche(siren) -> dict` : GET `/v2/entreprise` (`siren`, `api_token`) → nom,
  SIREN, forme juridique, date de création, code NAF + libellé, effectif,
  siège (ville), dirigeants (3 max, nom + qualité), derniers comptes
  (année, chiffre d'affaires, résultat net) quand présents. Timeout 10 s,
  cache mémoire 24 h par SIREN, jamais d'exception hors du module (retour
  `None` + `notifier_fournisseur("pappers", …, bascule=True)`).
- `sources_pappers(noms: list[str], compteur) -> list[SearchResult]` : un
  `SearchResult` par société trouvée, `provider="pappers"`, `url` =
  `https://www.pappers.fr/entreprise/<slug>-<siren>`, `snippet` = fiche en
  une phrase structurée (« SAS créée en 2019, NAF 62.01Z, 45 salariés, CA 2024
  3,2 M€, résultat 0,4 M€, dirigeants : … »).
- Dans `run_analysis`, pour `etude_marche` et `analyse_concurrentielle`
  (directive `sources.pappers = True`) : les noms de sociétés viennent (a) de
  la question et du profil (`company_name`) et (b) d'une extraction par le
  modèle tier `chat` sur les titres/extraits web déjà collectés (« liste
  jusqu'à 8 noms d'entreprises françaises mentionnées ») ; 8 fiches max ;
  résultats ajoutés au pool web AVANT le rerank final (le reranker juge de
  leur place). Tarif `tarif_recherche_pappers_micro_eur = 20_000` (≈ 2 cts par
  fiche, à confirmer selon l'abonnement). Citation affichée « (registre :
  pappers.fr) ».

## 5. Base de connaissance Axial (`app/modules/kb/`)

Existant à respecter : collection `knowledge_base`, payload `user_id="__kb__"`,
`doc_id` (uuid5 du fichier), `chunk_index`, `text`, `title`, `filename`,
`category` (`01_macro-institutionnel` … `06_litterature-strategie`),
`source`, `sector`. Les nouveaux points utilisent le MÊME payload
(`user_id="__kb__"`, `category="07_ajouts-admin"` par défaut, ou une
catégorie choisie dans la liste existante), pour que la lecture reste
uniforme. La table `kb_documents` est **remplie au premier listage** à partir
des `doc_id` distincts déjà présents dans Qdrant (titre, fichier, catégorie,
nombre de chunks, `cree_par = NULL`, `source = "ingestion initiale 08/2026"`),
puis tenue à jour par les routes.

- Table `kb_documents` (migration `0024_sources_v2`) : `id` UUID, `titre`,
  `source` (nom de fichier ou URL), `type` (`fichier` | `url`), `mime_type`,
  `nb_chunks`, `taille_octets`, `cree_par` (user id admin), `created_at`,
  `statut` (`indexe` | `echec`), `erreur` (texte, nullable).
- Service : `ingerer_fichier(db, admin_id, filename, data, mime)` et
  `ingerer_url(db, admin_id, url)` (téléchargement `httpx` 20 s, extraction
  texte HTML via `extract` existant si possible sinon nettoyage des balises ;
  PDF distant accepté) → chunk + embed (mêmes fonctions que `documents`) →
  `vector_store.upsert_chunks(doc_id, user_id="kb", chunks, vectors,
  collection=KB_COLLECTION, extra_payload={"titre", "source", "kb": True})`.
  `supprimer(db, doc_id)` retire la ligne et les vecteurs. `lister(db)`.
- Routes admin (`get_current_admin`) : `POST /admin/kb/fichiers` (multipart),
  `POST /admin/kb/urls {url}`, `GET /admin/kb`, `DELETE /admin/kb/{id}`.
- `rag.service.retrieve` : les passages issus de `KB_COLLECTION` portent
  `origine="kb"` et `titre` ; `grounding.assemble` les étiquette « (base
  Axial : <titre>) » et la citation `source="kb"`. Le front affiche « Base
  de connaissance Axial ».
- Front, Pilotage (admin) : section « Base de connaissance Axial » — dépôt de
  fichier, champ URL + « Ajouter », liste (titre, source, type, chunks, date,
  statut) avec suppression confirmée. Bridge : `axKbLister`, `axKbAjouterFichier`,
  `axKbAjouterUrl`, `axKbSupprimer`.

## 6. Drive comme source

- Backend : `POST /integrations/google/importer {file_id, name, mime_type}`
  (auth) : avec le jeton Google de l'utilisateur, `GET
  https://www.googleapis.com/drive/v3/files/{id}?alt=media` pour un fichier
  binaire, ou `/export?mimeType=` pour un Google Doc (→ `text/plain`) / Sheet
  (→ `text/csv`) / Slides (→ `application/pdf`) ; puis `documents.ingest`
  (mêmes formats, mêmes limites). Réponse = le document créé. Erreurs
  nommées : `google_non_connecte`, `drive_fichier_inaccessible`,
  `unsupported_format`.
- Le scope OAuth reste `drive.file` : l'utilisateur choisit ses fichiers via
  le **Google Picker** côté front (`https://apis.google.com/js/api.js`, vue
  `DocsView`), ce qui accorde l'accès fichier par fichier sans scope
  restreint. Le bouton « Importer depuis Drive » (surface Mémoire) n'apparaît
  que si `GET /integrations/status` déclare Google configuré ET si
  `NEXT_PUBLIC_GOOGLE_API_KEY` / `NEXT_PUBLIC_GOOGLE_CLIENT_ID` sont présents ;
  si Google n'est pas connecté, le bouton mène à la connexion.
- `GET /integrations/status` expose `google.selecteur` = booléen.

## 7. Sources par type de rapport (`ANALYSIS_DIRECTIVES[...]["sources"]`)

Champ ajouté à chaque directive, lu par `run_analysis` :
```python
"sources": {"web": True, "rag": True, "notion": True,
            "investisseurs": False, "pappers": False}
```
`etude_marche` et `analyse_concurrentielle` : `pappers: True` ;
`cartographie_investisseurs` : `investisseurs: True`. Les contraintes de
fraîcheur/domaines viennent de `contraintes_pour(question, type)` (§1). Une
source à `False` n'est pas appelée. Test : chaque directive porte le champ
avec les cinq clés.

## 8. Santé réelle des fournisseurs

`GET /health/providers?reel=1` (admin) exécute un appel de test court par
fournisseur configuré (recherche « test » sur chaque moteur, `generate` de
5 tokens sur Gemini et Claude, `rerank` de 2 documents, `rechercher("Axial")`
sur Pappers si clé) avec timeout 8 s chacun, en parallèle ; réponse
`{name, configured, ok, latence_ms, erreur}`. Sans `reel`, comportement
actuel (statique).
